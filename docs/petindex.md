# 进化链:包与组(`scripts/petindex.py`)

进化链只在这一处算,**全部消费方同一口径**:

| 粒度 | 产物 | 谁用 |
| --- | --- | --- |
| **包**:按图鉴号归并进化链,`<图鉴号>-<链首名>` | `gen.sh --chains <file>`(`--format json`)→ rocom-pets 的 `data/chains.json`;`names.json` 里 `petbase[].cb`(链首图鉴号,与自身图鉴号相同时省略) | rocom-pets 的导出器 / 客户端 / Worker 按包找资产;rocom-agent 按 `cb` 把同族宠物排到一起 |
| **组**:按进化关系求连通分量,组号 = 组内最小 petbase_id | `names.json` 里 `petbase[].e` | rocom-capture 详情页按它画整条链(分支并列) |

包比组粗:板板壳的两种外观是两条链、两个组,却是一个包(图鉴号相同);组又比 PET_EVOLUTION_CONF
粗一点:「被污染的星星眼」那批与伊里斯(独角兽链的第二个一阶)靠 `pet_evolution_id` 挂回本体的组。
`gen_gamedata.py` 生成时核对**链上列到的每个形态**包的图鉴号 = 组内最小图鉴号,不一致打 `!!`。
经别名认回的行(下面「野外首领…(废弃)」那种)不核对:它们抄的图鉴号本来就靠不住。

```sh
uv run python scripts/petindex.py                # 下面这份清单
uv run python scripts/petindex.py --format tsv   # 同样的内容,制表符分隔,好往表格里贴
uv run python scripts/petindex.py --format json  # rocom-pets 的 data/chains.json(gen.sh --chains 即它)
uv run python scripts/petindex.py --check        # 拿六条样例回归(改了规则先跑这个)
```

数据来自 `scripts/unpack.sh` 产物(默认 `~/Downloads/rocom/parsed`,也认 `$ROCOM_PARSED` 与 `--parsed`)。
**这份清单是生成物,别手改** —— 要改改脚本。

规模:**267 个包 / 760 个形态**。其中有图鉴号的 192 个包 / 601 个形态,
没图鉴号的归到 `000`,75 个包 / 159 个形态。

## 归并规则

**1. 包名 = `图鉴号-链首名`**(也是包目录名),图鉴号取链首的 `PETBASE_CONF.pictorial_book_id`,
补足三位;**没有图鉴号的一律记 `000`**。

这一位是**归并键**,也是排序键:同一只宠物的两种外观(两条链,如海盔虫)落进同一个包;
**真的不同宠物碰了同名**(大耳帽兜、逗逗)靠图鉴号各归各位(`142-大耳帽兜` / `144-大耳帽兜`)。

`000` 这一档里同名的包会不会撞?这份数据里没撞(75 个包名两两不同)。真撞了脚本会往 stderr
打一行 `!! 包名 … 被 N 个包共用`,别硬用 —— 号已经不解决问题了。

**2. 形态来自 `PET_EVOLUTION_CONF`**,不是顺着 `PETBASE_CONF.evolution_pet_id` 自己爬。

`evolution_chain` 是普通形态。爬 `evolution_pet_id` 会漏:那个字段在分支链上是**一串**
(矿晶虫指着六个),只取第一个会把另外五条外观整条丢掉。

**王者形态从 `PETBASE_CONF` 那边找**:王者形态那行自己写一个 `pet_evolution_id` 指回链,
认「`stage == 4` 且 `is_boss == 1`」的行(全表 67 行,64 行带这个反查字段)。不认这条就会
整批丢掉 64 个形态 —— 它们有图鉴号,又进不了「没图鉴号的收养」那一步。

另有一套 6xxx 的**首领形态**(`卡图斯（初级/中级/高级）` 那 34 行):三行一只、
共用同一份 `…Bo_001` 模型,只是首领等级不同。**它们不是王者形态**,也没有图鉴号 ——
王者形态先占了那份资产,它们就自然落空,所以清单里仍是「钻石蜗」而不是「戴蒙德（初级）」。

**3. 同名同资产 = 同一个形态**,多出来的算「外观」,记作 `名字xN`。

判重看的是**资产目录名**(`MODEL_CONF.path` 里 `/Pets/` 后面那一段),不是 `model_conf` 自己:
同一个王者形态在表里有三四行(千棘海针 4020 / 5012 / 8106,给图鉴、王者战斗等不同场合各配
一行),`model_conf` 各不相同,指的却是同一份 `Wat_HaiKuiChongBo_001`。而换外观是真换资产
(`Wat_HaiKuiChong1_001` vs `Wat_HaiKuiChong1Ar_001`),所以 x6 那种数量不会被误并。

**4. 排序看资产名里的阶段位**(`Gra_MiaoMiao2_001` → 二阶),不是配置里的 `stage` 字段。

那个字段是**相对本条链**的:路路尼自己那条链只有它一个,写着 `stage 1`,可它明明是二阶。
把散落的成员认回来之后就会排成「路路尼/路路/古路尼」。资产名里的数字是绝对的。
王者形态(`…Bo_001`,没有数字)例外,按 petbase id 的先后排(那正是游戏内的顺序),一律垫底。

**5. 外观标签**先取 `MEGAMAP_CONF`(`genre` 写成「刺盔虫_本来的样子」,`icon` 就是 petbase_id),
没有就取链名里的括号(「矿晶虫进化链(西瓜碧玺的样子)」)。

链名那一路是**给 MEGAMAP 补漏的**:那张表只登记「特殊的那一版」,基础版往往没条目
(脆筒甜甜的樱桃巧克力口味就只在链名里)。链名写「…分支」的不算外观(果冻那三条链是
分支去向、不是长相),否则会写出「x3 表示有 抹茶布丁分支」这种莫名其妙的话。

## 没有图鉴号的那批(`000`)

这批分两种。一种在 `PET_EVOLUTION_CONF` 里有链(只是链首没图鉴号),照常读;
另一种连链都没有 —— 它们在 `evolution_pet_id` 里**一条边都没有**,得靠**资产名的词干**
重新拼(`Gra_RuoYeXi1_001` / `…2_001` / `…3_001` → 若叶蜥→立叶蜥→蝶叶巨蜥),
即 design.md §2 里那条「资源目录名数字后缀 = 阶段」,这里从交叉校验升成了主依据。

没有图鉴号可当归并键,所以 `000` 这一档改用**链首资产的词干**分包:同根的几条分支链
(菌宝那四条)并成一个,换外观的几条(雪毛角羚牛那三条,`…1_001` / `…1Ar_001` / `…1Ar_002`)
也并成一个。

**但链首顶着别人的模型时不能用词干。** `Com_YaJiJi1_001` 是鸭吉吉(011)的模型,却被
**53 个还没做自己模型的宠物**拿去顶着;按词干分的话,五条毫不相干的链(呆火鸟、荆伞兽、
蝶兰花、笔童、蛐曲儿……)会并成一个二十几形态的怪包。所以:有图鉴号的包先占资产,
没图鉴号的**不许抢已经有主的资产**,链首被挡掉的就退回按链首 id 各归各的,
包名也跟着改成留下来的头一环(不然会出现一个叫「呆火鸟」、里面根本没有呆火鸟的包)。

不收的五类:

- 链名带**「废弃」**的两条(野外首领梦想三三 / 雪影娃娃)—— 它们仨成员指的是同一份 BOSS 模型;

- 名字带**「占位」**的(数据自己这么写的,15 行);
- **`首领-xxx`**(BOSS 行,和本体同一份模型);
- `legal_petbase == 0`(明确作废);
- **`MODEL_CONF.path` 里没有 `/Pets/…`** 的四行(幸运惊喜盒 ×3、随机精灵)——
  界面上的占位条目,没有资产目录也就无从导出。

## 两处推断(不是数据直说的,复核请从这儿看起)

**一、4 个形态的基础外观在数据里没名字**,按惯例补了「本来的样子」:
171-波波螺的 波波螺 / 消波螺 / 嗜波螺,360-加油海葵的 加油蟹。
这四个字数据里没有,但正是游戏自己在肯登记时用的说法(板板壳_本来的样子、
冬羽雀_本来的样子),不是另造一套词。只在「孤零零一个没名字、其余都有」时才补 ——
两个都没名字就说明这不是「基础版 + 特殊版」那种结构,瞎补会把话说错。

**二、7 个没图鉴号的形态按资产词干认回了原包**,而不是丢进 `000`:

| 认进 | 形态 | 资产 |
|---|---|---|
| `000-赤毛鸡仔` | 伊丽莎白 | `Fir_JiZai3_001` |
| `000-路路` | 路路、古路尼 | `Poi_LuLu1_001`、`Poi_LuLu3_001` |
| `150-里奥` | 圣羽翼王(第二种外观) | `Win_LiAo3Ar_001` |
| `244-翡翠水母` | 琉璃君主(王者) | `Wat_ShuiMuBo_001` |
| `036-小鼠獭` | 卷发巨獭(王者) | `Wat_ShuTaBo_001` |
| `095-记忆石` | 记忆石(第二种外观) | `Roc_JiYiShi1_011` |

它们的词干和某个已有的包对得上,就是那条链缺的一环 —— 丢进 `000` 会把一条链劈成两个包,
正好和「规范化合并」反着来。`路路` 那个包连名字都跟着改了:收进一阶的 路路 之后,
包名从 `000-路路尼` 变成 `000-路路`(规则 1 说包名跟链首走)。

跑 `tools/petindex.py` 时这两处都会打到 stderr,不会悄悄混进清单。
